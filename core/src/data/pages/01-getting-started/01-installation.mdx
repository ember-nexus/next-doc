# Installation

Ember Nexus is available on [Docker](https://hub.docker.com/r/embernexus/api) for AMD and ARM architectures.

Additional architectures like RISC V are planned to be supported at some point in the future, but require additional
work in upstream dependencies.

## Requirements

**Hardware requirements**: Normal deployments require at least 8 GB of RAM, because both Neo4j and Elasticsearch -
mandatory components of the Ember Nexus deployment - are Java based and can consume a lot of memory.

**Software requirements**: Docker is required.

## Dependencies

Ember Nexus requires several databases to be available:

- [Neo4j](https://neo4j.com)
- [MongoDB](https://www.mongodb.com)
- [Elasticsearch](https://www.elastic.co/elasticsearch)
- [S3](https://aws.amazon.com/s3) compatible storage API, e.g. [MinIO](https://www.min.io)
- [Redis](https://redis.io)
- [RabbitMQ](https://www.rabbitmq.com)

All the dependencies can be operated as Docker containers as well.

## Docker Compose

```yml
services:

  api:
    container_name: api
    build:
      context: ..
      dockerfile: ./docker/Dockerfile
      target: development
    volumes:
      - ./well-known-security.txt:/well-known-security.txt
    ports:
      - "80:80"

  neo4j:
    container_name: neo4j
    image: neo4j:5.25
    environment:
      - NEO4J_AUTH=neo4j/password
    ports:
      - "7474:7474"
      - "7687:7687"

  mongodb:
    container_name: mongodb
    image: mongo:8.0
    ports:
      - "27017:27017"
    environment:
      - MONGO_INITDB_ROOT_USERNAME=mongodb
      - MONGO_INITDB_ROOT_PASSWORD=password
      - GLIBC_TUNABLES="glibc.cpu.hwcaps=-SHSTK" # see https://github.com/docker-library/mongo/discussions/748#discussioncomment-15927486

  elasticsearch:
    container_name: elasticsearch
    image: elasticsearch:8.16.1
    ports:
      - "9200:9200"
    environment:
      - discovery.type=single-node
      - xpack.security.enabled=false
      - xpack.security.enrollment.enabled=true

  redis:
    container_name: redis
    image: redis:8.0-M02
    ports:
      - "6379:6379"
    command: redis-server --save 20 1 --loglevel warning --requirepass redis-password

  rabbitmq:
    container_name: rabbitmq
    image: rabbitmq:3-management
    ports:
      - "5672:5672"
      - "15672:15672"
    environment:
      - RABBITMQ_DEFAULT_USER=user
      - RABBITMQ_DEFAULT_PASS=password

  minio:
    container_name: minio
    image: quay.io/minio/minio:latest
    ports:
      - "9000:9000"
      - "9001:9001"
    volumes:
      - ../volumes/minio:/data
    environment:
      - MINIO_ROOT_USER=ROOTNAME
      - MINIO_ROOT_PASSWORD=CHANGEME123
    command: server /data --console-address ":9001"
```

**Note**: This setup is for demonstration purposes only, and should not be directly used for production systems.
Especially volumes and security relevant settings should be adapted to your setup.

## Reverse proxy

Ember Nexus is designed to be used behind a reverse proxy like [Traefik](https://traefik.io/traefik) or
[Caddy](https://caddyserver.com/), and for that reason, it does not offer options to configure TLS and similar settings
itself.

## High-availability setup (HA)

Ember Nexus can be scaled up without any further configuration. Simply add additional containers with the same database
access, configuration and ENV variables, and everything works out of the box :D

The database services can be scaled up independently as well. Both community and enterprise editions are compatible with
Ember Nexus.
