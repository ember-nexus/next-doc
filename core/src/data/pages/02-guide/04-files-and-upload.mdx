title: Files and upload
---

Every node and relation can be assigned a single file. This file can be of any content and length - from zero bytes up
to 5 TB by default configurations, given the Ember Nexus API server has that much storage capacity to begin with.

All access rules from the element itself transfer to its file as well. I.e. if a user can read the element, then the
same user can also read the element's file.

Files can be either uploaded directly in a single request, or using multiple smaller requests in a resumable upload. The
latter is especially useful for bigger files (100+ MB) or when the network is unreliable and individual requests might
fail / need to be repeated.

Some metadata of files is automatically stored as special element properties, e.g. the file's name (if provided) and
size of the file in bytes. These metadata properties can not be manually changed by the user, unless he replaces the
file.

## Uploading a file directly

```bash
curl -v \
  -H 'Authorization: Bearer secret-token:1nc1pFdBO2QLYRMMvULgtQ' \
  -H 'Content-Disposition: inline; filename=image.jpg' \
  --data-binary @./image.jpg \
  https://api.example.com/7ac83b11-3c48-4ecd-930c-97e9dbf47ef3/file
```

**Note**: A file upload using `POST` will fail, if the element already has a file.

**Note**: The filename is set through the `Content-Disposition`-header. In simple cases like the example, the filename
can be directly written as-is, however filenames with non-ASCII characters need to be encoded. See
[MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Disposition#filename) and
[http.dev](https://http.dev/content-disposition#filename) for details.

## Replacing a file directly

Similar to the previous `POST` operation, the `PUT` upload endpoint can be used to upload a new file. However, this
endpoint does not care whether the element already has an associated file - it either writes it, or replaces it.

```bash
curl -X PUT -v \
  -H 'Authorization: Bearer secret-token:1nc1pFdBO2QLYRMMvULgtQ' \
  -H 'Content-Disposition: inline; filename=image.jpg' \
  --data-binary @./image.jpg \
  https://api.example.com/7ac83b11-3c48-4ecd-930c-97e9dbf47ef3/file
```

## Downloading a file

```bash
curl -v \
  -H 'Authorization: Bearer secret-token:1nc1pFdBO2QLYRMMvULgtQ' \
  -o download.jpg \
  https://api.example.com/7ac83b11-3c48-4ecd-930c-97e9dbf47ef3/file
```

### Downloading part of a file

A `Range` header downloads a byte range instead of the whole file - useful for resuming an interrupted download, or
streaming media:

```bash
curl -v \
  -H 'Authorization: Bearer secret-token:1nc1pFdBO2QLYRMMvULgtQ' \
  -H 'Range: bytes=0-1048575' \
  -o download.jpg.part \
  https://api.example.com/7ac83b11-3c48-4ecd-930c-97e9dbf47ef3/file
```

A satisfiable range responds with `206 Partial Content` and a `Content-Range` header; only a single range per request
is supported. See [`GET /<uuid>/file`](/api/get-element-file) for the full set of error cases.

### Verifying file integrity

Every download's response includes a `Repr-Digest` header with the file's SHA-256 hash
([RFC 9530](https://datatracker.ietf.org/doc/html/rfc9530) format), so a client can verify the downloaded bytes
without a separate request or checksum file. The same mechanism works in reverse on upload: sending a `Repr-Digest`
header lets the server verify the uploaded bytes and reject a corrupted upload with `400 Bad Request` before it is
stored - see [`POST /<uuid>/file`](/api/post-element-file) and [`PATCH /upload/<uuid>`](/api/patch-upload).

## Deleting a file

```bash
curl -X DELETE -v \
  -H 'Authorization: Bearer secret-token:1nc1pFdBO2QLYRMMvULgtQ' \
  https://api.example.com/7ac83b11-3c48-4ecd-930c-97e9dbf47ef3/file
```

## Uploading a file in multiple chunks (resumable upload)

The resumable upload process implements the upcoming web standard
["Resumable Uploads for HTTP"](https://datatracker.ietf.org/doc/draft-ietf-httpbis-resumable-upload/) IETF draft.

It works in the following way:

- Create a new resumable upload object.
- Upload chunks of data until finished.
- If any chunk uploads failed, query the current upload offset, and resume your upload.
- Finish the upload. This merges all chunks to a single file, which is then associated with your element. The resumable
  upload object is then destroyed automatically.

### Limitations and side effects of resumable uploads

- Resumable uploads expire three hours after the first request (configurable).
- All chunks of a resumable upload except the last one must be at least 5 MB big - a limitation by S3.
- The maximum size of a single chunk is 100 MB (technically 101 MiB for the whole request, configurable).
- The maximum number of chunks per resumable upload is 10.000 (configurable).
- Additional limits of the S3 upload and storage buckets might apply.
- You can send the expected total upload length ahead of time, which will be used to verify the length of the upload at
  the end. However, this is optional, and uploads of unknown length are supported.
- The expected upload length, once set, can not be changed or removed.
- The resumable upload must happen sequentially, i.e. the first chunk must be received before the second chunk can be
  processed. Sending out-of-order chunks will result in `400 bad request` exceptions.
- Access control:
  - Only the user who created the resumable upload object can use and finish the upload.
  - A resumable upload object is not transferable to other users.
  - Should the user lose access to the target element of the resumable upload, then the resumable upload will be
    canceled and deleted.
- Concurrency: Multiple parallel resumable uploads to the same target element are supported (and discouraged). Once the
  uploads finish, they will overwrite the file of previous uploads. The upload which is finished last will be the
  "winning" upload.

### Splitting the file into chunks

The following command can be used to split a single file into multiple smaller chunks with a numeric index:

```bash
split -b 10M -d image.jpg image.jpg. --additional-suffix=.part
```

### Creating a resumable upload object

Similar to a direct upload, both `POST` and `PUT` can be used.

The important detail for resumable upload creation is, that the header `Upload-Complete` with the value `?0` is sent.
`?0` is ["boolean false"](https://www.ietf.org/rfc/rfc8941#name-booleans), and it has the meaning that the upload is
incomplete, thereby creating a resumable upload.

```bash
curl -X PUT -v \
  -H 'Authorization: Bearer secret-token:1nc1pFdBO2QLYRMMvULgtQ' \
  -H 'Content-Disposition: inline; filename=image.jpg' \
  -H 'Content-Type: image/png' \
  -H 'Upload-Complete: ?0' \
  --data-binary @./image.jpg.01.part \
  https://api.example.com/7ac83b11-3c48-4ecd-930c-97e9dbf47ef3/file
```

The response then contains the `location` header, which is the location of the newly created resumable upload object.

### Uploading a chunk

Using the location of the resumable upload object, new chunks can be uploaded using the `PATCH` operation:

```bash
curl -X PATCH -v \
  -H 'Authorization: Bearer secret-token:1nc1pFdBO2QLYRMMvULgtQ' \
  -H 'Content-Type: application/partial-upload' \
  -H 'Upload-Complete: ?0' \
  -H 'Upload-Offset: 10485760' \
  --data-binary @./image.jpg.02.part \
  https://api.example.com/upload/98e795bc-cbe8-49d2-a5ce-e6977b877139
```

### Querying the current upload offset

`HEAD` returns the current upload offset, as well as additional metadata, if available:

```bash
curl -I -v \
  -H 'Authorization: Bearer secret-token:1nc1pFdBO2QLYRMMvULgtQ' \
  https://api.example.com/upload/ec19e774-b54d-43d7-b167-e3c35441b6fa
```

### Sending the last chunk

To complete the resumable upload, you have to send the HTTP header `Upload-Complete` with the value `?1` (boolean true).

```bash
curl -X PATCH -v \
  -H 'Authorization: Bearer secret-token:1nc1pFdBO2QLYRMMvULgtQ' \
  -H 'Content-Type: application/partial-upload' \
  -H 'Upload-Complete: ?1' \
  -H 'Upload-Offset: 20971520' \
  --data-binary @./image.jpg.03.part \
  https://api.example.com/upload/93c842b6-60a7-419e-aa39-17b31d504b90
```

### Canceling a resumable upload

```bash
curl -X DELETE -v \
  -H 'Authorization: Bearer secret-token:1nc1pFdBO2QLYRMMvULgtQ' \
  https://api.example.com/upload/93c842b6-60a7-419e-aa39-17b31d504b90
```
