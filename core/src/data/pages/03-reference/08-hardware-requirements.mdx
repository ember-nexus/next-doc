Ember Nexus API and the databases it depends on can run on a range of CPU architectures, but hardware
sizing differs a lot between a local/development setup and a production deployment. This page covers both.

## Supported CPU architectures

| Software | amd64 | arm64 | riscv64 | ppc64le | s390x | mips64le |
| --- | --- | --- | --- | --- | --- | --- |
| Ember Nexus API | Supported (1) | Supported (2) | Planned (3) | Not planned (4) | Not planned (4) | Not planned (4) |
| Neo4j | Supported (5) | Supported (5) | Experimental (6) | Experimental (6) | Experimental (6) | Not runnable (7) |
| MongoDB | Supported (8) | Supported (8) | Not runnable (7) | Enterprise only (9) | Enterprise only (9) | Not runnable (7) |
| Elasticsearch | Supported (10) | Supported (10) | Experimental (6) | Experimental (6) | Experimental (6) | Not runnable (7) |
| Redis | Supported (11) | Supported (11) | Experimental (12) | Supported (11) | Supported (11) | Supported (11) |
| RabbitMQ | Supported (13) | Supported (13) | Not planned (14) | Supported (13) | Supported (13) | Not runnable (7) |
| MinIO | Supported (15) | Supported (15) | Not supported (16) | Supported (15) | Supported (15) | Supported (17) |

1. `amd64` is supported by default.
2. `arm64` is supported since Ember Nexus API 0.0.23.
3. `riscv64` will likely be supported once computers and CI/CD infrastructure are more available and the ecosystem is
   more stable; see also [PHP's tracking issue](https://github.com/docker-library/php/issues/1279). Open a
   [GitHub issue](https://github.com/ember-nexus/api/issues) if you need this.
4. No support is currently planned for `ppc64le`, `s390x` or `mips64le`. This would likely require hardware donation
   or collaboration - open a [GitHub issue](https://github.com/ember-nexus/api/issues) if you're interested.
5. Neo4j [officially supports](https://neo4j.com/docs/operations-manual/current/installation/requirements/) `amd64`
   and `arm64`.
6. No official support, although Java applications should generally be able to run on these architectures.
7. The software cannot run on this architecture at all.
8. MongoDB [officially supports](https://www.mongodb.com/docs/manual/installation/#supported-platforms) `amd64` and
   `arm64` in its community and enterprise editions.
9. MongoDB supports `ppc64le` and `s390x` only in
   [enterprise-only builds](https://www.mongodb.com/docs/manual/installation/#supported-platforms).
10. Elasticsearch [officially supports](https://www.elastic.co/support/matrix) `amd64` and `arm64`.
11. Redis [supports most architectures](https://hub.docker.com/_/redis).
12. Redis seems to be [experimentally runnable](https://github.com/redis/redis/pull/12349) on RISC-V.
13. RabbitMQ supports [most platforms Erlang covers](https://www.rabbitmq.com/platforms.html).
14. RabbitMQ [might support](https://www.rabbitmq.com/platforms.html) RISC-V once it is
    [supported by Erlang](https://github.com/erlang/otp/issues/7498).
15. MinIO [supports](https://www.min.io/docs/minio/linux/operations/install-deploy-manage/deploy-minio-single-node-multi-drive.html#download-the-minio-server)
    `amd64`, `arm64`, `ppc64le` and `s390x`.
16. MinIO [does not yet support](https://github.com/minio/minio/pull/17161) RISC-V, although there is some community
    work underway.
17. MinIO [seems to support](https://github.com/minio/minio/blob/adb8be069ee18f5360c2a9dcd22054b113493fec/buildscripts/cross-compile.sh#L12C34-L12C44)
    `mips64`, although no image is published for it through Docker.

If any of this information needs correcting, please open a [GitHub issue](https://github.com/ember-nexus/api/issues).

## Local and development setups

For local and development purposes, the whole stack can be hosted on a single machine with at least 8 GB of RAM,
4+ vCPUs, and 10 GB of SSD storage - see the [installation guide](/getting-started/installation) for a ready-to-use
Docker Compose file.

<Note title="Not suitable for production">
This single-machine setup is not recommended for production use: services like Elasticsearch can consume enough RAM
to starve the other services, and because nothing is distributed, a single storage-layer crash takes down the whole
stack.
</Note>

## Production setups

For production, it's recommended that each service run in its own compute instance, ideally in a cluster setup.
Using managed/SaaS products is possible, but increased network latency between services can translate directly into
increased API response times - keep all services as close to each other as possible for the best performance.

### Neo4j

- Self-hosted community edition: at least 1 GB RAM, 1+ vCPU, and 10+ GB storage
  ([source](https://neo4j.com/docs/operations-manual/current/installation/requirements/#deployment-requirements-hardware)).
- Self-hosted cluster: at least 3 compute instances with 1+ GB RAM, 1+ vCPU, and 10+ GB storage each - requires the
  enterprise edition ([source](https://neo4j.com/docs/operations-manual/current/clustering/setup/deploy/)).
- SaaS: [Neo4j AuraDB](https://neo4j.com/cloud/platform/aura-graph-database/).

Alternatively, any graph database that supports openCypher and Bolt 4.4+ can be used, e.g. Memgraph.

### MongoDB

- Self-hosted: at least 4 GB RAM, 1+ vCPU, and 10+ GB storage
  ([source](https://www.mongodb.com/docs/cloud-manager/tutorial/provisioning-prep/#hardware-and-software)).
- Clusters and SaaS: [MongoDB Atlas](https://www.mongodb.com/atlas/database).

### Elasticsearch

- Self-hosted: at least 4 GB RAM, 1+ vCPU, and 10+ GB storage.
- Clusters: multiple self-hosted clustering options are available.
- SaaS: [Elastic Cloud](https://www.elastic.co/cloud/).

### Redis

- Self-hosted: at least 4 GB RAM, 1+ vCPU, and 10+ GB storage.
- Clusters: see [Redis's scaling documentation](https://redis.io/docs/management/scaling/).
- SaaS: Redis Enterprise Cloud and similar managed offerings are available.

### RabbitMQ

- Self-hosted: at least 1 GB RAM, 1+ vCPU, and 1+ GB storage.
- Clusters: see [RabbitMQ's clustering documentation](https://www.rabbitmq.com/clustering.html).
- SaaS: there is no official SaaS offering, but third parties provide RabbitMQ SaaS.

### S3-compatible object storage (MinIO)

- Self-hosted: at least 1 GB RAM, 1+ vCPU, and 10+ GB storage.
- Clusters: see [MinIO's multi-node deployment documentation](https://www.min.io/docs/minio/linux/operations/install-deploy-manage/deploy-minio-multi-node-multi-drive.html).

Alternatively, any other S3-compatible object storage API can and should be used if one is already available to you.
